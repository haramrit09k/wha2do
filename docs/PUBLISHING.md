# Publishing wha2do on Google Play

This is the end-to-end checklist for getting a signed release into the Play Console. Items marked **you** need
your own accounts or secrets, so they cannot be done from the repository.

> Play policies change often. Where this guide names a policy, check the Play Console's own wording for the
> current rules before you submit.

## 1. What is already done in the repo

| Requirement | Status |
| --- | --- |
| Modern target SDK | `targetSdk 36`, `compileSdk 37`, `minSdk 24` (React Native 0.88) |
| App bundle (`.aab`) output | `npm run build:aab` |

| Privacy policy draft | `docs/privacy-policy.md` |

## 2. The package name and the 2020 Play listing

wha2do was first published on Google Play in 2020 as **`com.wha2do`**, and the app now uses that same package
name (`namespace` and `applicationId` in `android/app/build.gradle`). The package name is permanent per
listing, and a new version only counts as an *update* of the old listing if both of these match:

1. **The Play Console account that owns `com.wha2do`.** If you can no longer sign in to that developer account
   (for example it was a teammate's or a university one), you cannot update it.
2. **The signing key.** If the app was enrolled in **Play App Signing**, open Play Console, then the app,
   **Test and release, App integrity**, and use *Request upload key reset* if you lost the old key. If it was
   signed with a self-managed key (common for 2020 apps), you need that original `.jks`; without it you cannot
   update the listing.

If either is missing, publish as a brand-new app instead: change `namespace` and `applicationId` to a new id,
and move `android/app/src/main/java/com/wha2do/` and the `package` line in both Kotlin files to match.
The listing at `play.google.com/store/apps/details?id=com.wha2do` returned "not found" when checked in
October 2026, which usually means it was unpublished or removed; the Console will show the status and reason.

## 3. Use your own Firebase project (**you**)

The Firebase project in `src/firebase.js` came from the original coursework and may be gone or shared.

1. Create a project in the [Firebase console](https://console.firebase.google.com/).
2. Enable **Authentication, then Email/Password**, and create a **Realtime Database**.
3. Publish the rules in `database.rules.json` (each user can read and write only `users/<their uid>`).
4. Register a **Web app** in the project and paste its config into `src/firebase.js`.
5. In Google Cloud, restrict the API key to the APIs the app needs (Identity Toolkit and Firebase Realtime
   Database) and consider enabling Firebase App Check.

## 4. Create your upload key (**you**)

```bash
keytool -genkeypair -v -storetype PKCS12 -keystore wha2do-upload.jks \
  -alias wha2do-upload -keyalg RSA -keysize 2048 -validity 10000
```

Keep the `.jks` file and its passwords somewhere safe and backed up. Never commit them (`*.jks` and
`android/keystore.properties` are git-ignored). Then:

```bash
cp android/keystore.properties.example android/keystore.properties   # and fill it in
```

Use **Play App Signing** (the default for new apps): Google keeps the real app-signing key, and you only hold
the upload key, which can be reset if you lose it.

## 5. Build the release bundle

Requirements: Node 22.11+, JDK 17 or newer, Android SDK platform 37 and build-tools 37, NDK 27.1.12297006 and
CMake 3.22.1 (Android Studio installs them on first sync).

```bash
npm install
npm run build:aab
# -> android/app/build/outputs/bundle/release/app-release.aab
```

Each upload needs a higher `versionCode` (`android/app/build.gradle`). Bump `versionName` for user-visible
versions.

To test on a device first: `npm run build:apk` gives a signed APK you can sideload.

## 6. Play Console setup (**you**)

1. Create the app (name **wha2do**, default language, App, Free).
2. **Store listing**: copy the text from `store/listing.md`; upload `store/play-icon-512.png`,
   `store/feature-graphic-1024x500.png` and the screenshots in `store/screenshots/`.
3. **Privacy policy**: host `docs/privacy-policy.md` somewhere public (for example GitHub Pages or a Gist), fill in
   your contact email in it, and enter the URL.
4. **App access**: the app needs a login, so give reviewers a test account (create one in your Firebase project
   and enter the email and password here).
5. **Data safety**: see the draft answers below.
6. **Content rating** questionnaire (no user-to-user content, no ads, no purchases) and **Target audience**
   (13+ or general adult audience is simplest, do not select children).
7. **Ads**: none. **Government / health / finance apps**: no.
8. **Account deletion**: this app creates accounts, so Play asks for a deletion URL. Use the privacy-policy page
   URL, which explains the in-app path and the email fallback.
9. Upload the `.aab` to **Internal testing** first, install it from the Play link on a real phone, then promote.
   If your developer account is a personal one created recently, Play may require a closed test with a minimum
   number of testers for a minimum number of days before you can apply for production access. Check the Console
   for the current numbers.

### Draft Data safety answers (review them against the final app)

| Data type | Collected | Shared | Purpose | Optional |
| --- | --- | --- | --- | --- |
| Email address | Yes | No | Account management | No |
| Name (the username the person types) | Yes | No | Account management, app functionality | No |
| Phone number | Yes | No | Account profile (stored, not used for anything else yet) | No |
| User IDs (Firebase uid) | Yes | No | Account management | No |
| Other user-generated content (lists and tasks) | Yes | No | App functionality | No |

- Data is **encrypted in transit** (HTTPS).
- Users can **request deletion**: yes, in the app (Account, then Delete account) and by email.
- No ads, no analytics, no data sold. Firebase (Google) acts as a service provider, which Play does not count as
  "sharing".
- If you remove the phone-number field from sign-up (recommended, since it is not used), remove that row too.

## 7. Before you hit "Release"

- [ ] Installed the signed build from Internal testing on at least one real phone (a small and a large one if
      you can) and walked through sign up, add list, add task, tick, delete account, log back in.
- [ ] Checked the keyboard behaviour in the "new list" and "new task" sheets (it uses edge-to-edge layout, so
      verify the input stays visible above the keyboard).
- [ ] Privacy policy is live and the contact email is filled in.
- [ ] Firebase rules are published and the API key is restricted.
- [ ] Backed up the upload key and passwords.
